# 디톡스 투두 (Detox Todo) — 기획서

> 상태: 초안 (v0.1) · 최종 수정: 2026-08-16
> 이 문서는 계속 다듬어질 예정입니다. 열린 질문은 하단 참고.

---

## 1. 한 줄 정의

**투두리스트 + 포모도로 + 앱 차단**을 결합한 macOS 생산성 앱.
할 일을 하는 동안, 그 할 일에 방해되는 앱을 열려고 하면 "정말 지금?"이라고 묻는 관문이 뜬다.

## 2. 문제 정의

- 기존 투두 앱은 "무엇을 할지"만 관리하고, 실제로 딴짓을 막지는 못한다.
- 기존 차단 앱(Freedom, Cold Turkey 등)은 시간대·스케줄 기준으로 차단하지, **지금 하고 있는 특정 작업** 기준으로 차단하지 않는다.
- macOS는 구조적으로 서드파티 앱에 강한 시스템 차단 권한을 주지 않는다 (iOS Screen Time API와 달리). 완전한 하드 블록을 목표로 하면 이 제약에 계속 부딪힌다.

## 3. 핵심 철학: 소프트 프릭션 (Soft Friction)

이 앱은 사용자를 **가두지 않는다.** 대신 무의식적으로 손이 가는 순간에 **의식적 선택의 순간**을 강제로 끼워 넣는다.

- 완전 차단이 아니라 전체화면 관문(interstitial)을 띄운다.
- 사용자는 관문에서 "돌아갈지 / 계속 쓸지"를 선택한다.
- "계속 쓸게"를 선택해도 벌칙은 없다. 대신 **기록**된다.
- 그 기록이 집중도 점수·스트릭에 반영되어, 장기적으로 사용자가 스스로의 패턴을 보게 만든다.

> 이 철학 때문에 macOS의 권한 제약이 오히려 문제가 되지 않는다 — 애초에 강제로 막을 필요가 없는 설계다.

## 4. 핵심 루프

```
[대기 상태] 아무것도 차단 안 됨
      │
      │ 사용자가 "집중 세션" 시작 (투두 선택은 선택사항)
      ▼
[집중 세션 진행 중]
  유효 차단 목록 = 기본 차단 세트 ∪ (선택한 투두에 연결된 차단 그룹들)
      │
      │ 세션 중 차단 대상 앱을 활성화(포그라운드로 전환)하면
      ▼
[전체화면 관문 오버레이]
  "지금 집중 세션 중입니다"
      │
      ├─ [집중으로 돌아가기] → 세션 계속, 아무 기록도 안 남음 (또는 "저항 성공"으로 긍정 기록)
      │
      └─ [계속 쓸게]        → 세션은 계속 진행, '흐트러짐' 1회 기록
                              → 집중도 점수 / 스트릭에 반영
```

핵심 원칙: **어떤 선택을 해도 세션은 끊기지 않는다.** 유일한 결과는 "기록에 남는다"는 것.

## 5. 차단 구조 (2-레이어)

| 레이어                    | 켜지는 시점                         | 내용                                                       |
| ------------------------- | ----------------------------------- | ---------------------------------------------------------- |
| 기본 차단 세트 (baseline) | 집중 세션이 켜져 있는 동안 항상     | 평소에 안 쓰고 싶은 앱 (예: 인스타그램, 유튜브)            |
| 투두 연결 그룹            | 그 투두로 세션을 돌리는 동안만 추가 | 해당 작업에 방해되는 앱 (예: '코딩' 투두 → 디스코드, 슬랙) |

- 세션 하나의 유효 차단 목록 = 기본 세트 ∪ 투두에 붙은 그룹들
- 그룹은 재사용 가능한 단위다. 예: "SNS 그룹"을 여러 투두에 동시에 붙일 수 있음.
- 세션이 아예 없는 상태(대기 상태)에서는 아무것도 차단되지 않는다 — 즉 "24시간 상시 차단" 모드는 없음 (집중 세션 = 차단의 전제조건).

## 6. 기술 방향

- **플랫폼**: macOS 우선 (Windows는 추후 별도 엔진으로 확장 가능성 열어둠)
- **데스크탑 셸**: Electron + React + TypeScript (빌드 도구: `electron-vite`)
  - `BrowserWindow`의 1st-party 옵션(`focusable: false`, `alwaysOnTop` 레벨 조정)으로 포커스를 뺏지 않는 오버레이 구현 — 커뮤니티 우회(Tauri의 NSPanel 변환 같은) 없이 공식 API로 해결 가능
  - `electron-updater` 기반 자동 업데이트 — 차등 업데이트, 단계적 배포, 코드 서명까지 업계 표준으로 검증된 경로
- **앱 감지 (네이티브 헬퍼)**: 별도의 작은 **Swift CLI 헬퍼 바이너리**
  - `NSWorkspace`의 앱 활성화(activation) 알림을 구독해 이벤트 발생 시 stdout으로 JSON 라인 emit
  - Electron 메인 프로세스가 이 헬퍼를 자식 프로세스로 스폰해서 stdout을 스트림으로 읽음 (폴링이 아닌 이벤트 기반 → 지연 없이 즉시 감지)
  - Rust 불필요, Swift 코드 범위는 이 헬퍼 하나로 한정됨
  - 감지된 앱은 `bundleId`로 판별 (표시 이름이 아니라 번들 ID로 매칭해야 신뢰도 높음)
  - 특수 권한(Family Controls 등) 불필요 → v1 난이도를 크게 낮추는 선택
- **관문 UI**: Electron `BrowserWindow`(`focusable: false`, 최상단 레벨)로 전체화면 오버레이 구현. 감지 즉시 헬퍼 → 메인 프로세스 → 오버레이 창 표시로 이어짐
- **프론트엔드 데이터 레이어**: TanStack Query + axios — Kotlin Spring Boot REST API 호출, 캐싱·리페치·낙관적 업데이트(예: "계속 쓸게" 직후 통계 즉시 반영) 처리
- **스타일링**: Tailwind CSS + shadcn/ui
  - shadcn/ui는 컴포넌트를 라이브러리가 아닌 코드로 복사해 쓰는 방식이라 런타임 의존성이 없고, Radix UI 프리미티브 기반이라 접근성이 기본 보장됨 (관문 오버레이 같은 모달성 UI에 유리)
  - 다크모드/테마 시스템(`next-themes`)도 바로 재사용 가능 → 이후 통계 대시보드 제작 시에도 동일 스택 사용
- **백엔드 서버**: Kotlin + Spring Boot
  - 계정, 통계 대시보드 집계, 결제(구독) 연동을 위한 REST API 서버
  - 데스크탑 앱(Electron 렌더러)과는 순수 HTTP 통신 — 프레임워크 종류와 무관하게 독립적으로 개발 가능
- **배포**: App Store 밖 배포 — Developer ID 서명 + 노터라이즈 (Cold Turkey, Freedom과 동일 방식)
  - App Store 샌드박스에서는 다른 앱 감시가 원천 차단되므로 앱스토어 배포는 불가능

## 8. 통계 / 게임화 (핵심 기능, 부가 기능 아님)

"계속 쓸게"의 유일한 대가가 기록이기 때문에, 그 기록이 사용자에게 실제로 와닿아야 관문이 의미를 가진다. 따라서 통계 대시보드는 v1의 핵심 기능으로 취급한다.

포함 후보:

- 집중도 점수 (세션당 흐트러짐 횟수 기반)
- 연속 집중 스트릭
- 세션별 저항 성공 / 흐트러짐 비율
- 앱별 유혹 랭킹 (어떤 앱이 가장 자주 관문을 뚫었는지)

세부 점수 산식과 UI는 별도 문서(`02-stats-gamification.md`, 추후 작성)에서 다룬다.

## 9. MVP 범위 (1차 초안 — 추후 조정)

**포함:**

- 투두 CRUD
- 차단 그룹 생성/관리, 앱 등록(bundleId 기반)
- 투두 ↔ 차단 그룹 연결
- 포모도로 타이머 (집중/휴식)
- NSWorkspace 기반 앱 감지 + 전체화면 관문 오버레이
- 세션/흐트러짐 기록 저장 (백엔드 서버에 동기화)
- 기본 통계 대시보드 (스트릭, 집중도 점수)
- 계정 생성/로그인 (백엔드 연동 전제)

**제외 (추후 검토):**

- Windows/Linux 지원
- 결제/구독 기능 (백엔드 서버는 v1부터 두되, 결제 연동 자체는 이후 단계에서 붙임)
- 팀/공유 기능
- 알림·리마인더 시스템
