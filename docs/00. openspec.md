# OffDo — 기획서

> 상태: v0.2 (전면 개정) · 최종 수정: 2026-08-17
> v0.1은 "집중 세션 = 포모도로" 단독 중심이었으나, v0.2에서 **캘린더 + 그룹 + 할일** 중심으로 재구성했다.
> 핵심 철학(소프트 프릭션)과 포모도로·관문 메커니즘은 그대로 유지된다.

---

## 1. 한 줄 정의

**캘린더 기반 투두리스트 + 포모도로 + 앱 차단**을 결합한 macOS 생산성 앱.
날짜별·그룹별로 할 일을 관리하고, 어떤 그룹에 집중하는 동안 그 그룹에 방해되는 앱을 열려고 하면 "정말 지금?"이라고 묻는 관문이 뜬다.

## 2. 문제 정의

- 기존 투두 앱은 "무엇을 할지"만 관리하고, 실제로 딴짓을 막지는 못한다.
- 기존 차단 앱(Freedom, Cold Turkey 등)은 시간대·스케줄 기준으로 차단하지, **지금 하고 있는 특정 작업/맥락** 기준으로 차단하지 않는다.
- macOS는 구조적으로 서드파티 앱에 강한 시스템 차단 권한을 주지 않는다 (iOS Screen Time API와 달리). 완전한 하드 블록을 목표로 하면 이 제약에 계속 부딪힌다.

## 3. 핵심 철학: 소프트 프릭션 (Soft Friction)

이 앱은 사용자를 **가두지 않는다.** 대신 무의식적으로 손이 가는 순간에 **의식적 선택의 순간**을 강제로 끼워 넣는다.

- 완전 차단이 아니라 전체화면 관문(interstitial)을 띄운다.
- 사용자는 관문에서 "돌아갈지 / 계속 쓸지"를 선택한다.
- "계속 쓸게"를 선택해도 벌칙은 없다. 대신 **기록**된다.
- 그 기록이 집중도·스트릭에 반영되어, 장기적으로 사용자가 스스로의 패턴을 보게 만든다.

> 이 철학 때문에 macOS의 권한 제약이 오히려 문제가 되지 않는다 — 애초에 강제로 막을 필요가 없는 설계다.

## 4. 화면 구조 (Desktop App, 4-컬럼 레이아웃)

```
┌──────────┬──────────┬──────────────────────────┬─────────────────────┐
│ ① 탭      │ ② 그룹    │ ③ 주간 할일 뷰            │ ④ 제한 앱           │
│          │          │                          │                     │
│ Calendar │ 현대      │ ◀ 2026년 7.2   [오늘]     │ [앱/사이트 추가]     │
│  (v1)    │ 개인      │ 월 화 수 목 금 토 일       │                     │
│          │ 공부      │  ─────────────           │ 공통 제한 앱         │
│ Friends  │  ...     │  ▷ 현대  (포모도로 시작)  │  ▢ ▢ ▢ ...          │
│  (v3)    │          │  ☑ 작업1 Todo            │                     │
│          │          │   ☐ 세부작업 Todo         │ 선택 그룹 제한 앱     │
│          │          │   ☑ 세부작업 Todo         │  (현대 제한 앱)      │
│          │          │  (일정: v2, 구글캘린더)   │  ▢ ▢ ...            │
└──────────┴──────────┴──────────────────────────┴─────────────────────┘
```

- **① 탭**: 앱 최상위 내비게이션. v1은 **Calendar 탭만**. Friends 탭은 v3.
- **② 그룹**: 사용자가 만든 **할 일을 묶는 단위**(예: 현대=회사, 개인, 공부). 그룹을 선택하면 ③에는 그 그룹의 할 일만 보이고, **아무 그룹도 선택하지 않으면 전체 그룹의 할 일이 다 보인다.** (선택 = 필터)
- **③ 주간 할일 뷰**: 요일 선택 + 선택한 날짜의 할 일 목록. 각 할 일은 체크박스와 서브태스크를 가진다. 상단의 **청록색 `▷` 버튼으로 포모도로 세션을 시작**한다.
- **④ 제한 앱**: 공통 제한 앱(항상)과 선택 그룹 제한 앱(그 그룹에 집중할 때만)을 설정. 앱은 드래그 또는 "앱/사이트 추가"로 등록.

## 5. 핵심 개념

### 5-1. 그룹 (Group)

- 사용자가 만드는 **할 일 묶음 단위이자 제한 앱의 스코프**.
- 그룹마다 자기만의 제한 앱 세트를 가진다.
- 그룹은 ③의 필터로 동작한다: 선택 시 그 그룹 할 일만, 미선택 시 전체.
- v1은 **단일 계층**(서브그룹 없음).

### 5-2. 할 일 (Todo)

- 특정 **그룹**에 속하고 특정 **날짜(day)**에 귀속된다.
- **서브태스크**를 가진다 — v1은 **최대 3단계 중첩**까지 지원(추후 무한 중첩으로 확장).
- 완료 처리: **체크해도 목록에서 사라지지 않는다.** 완료 항목은 취소선 처리 후 **목록 하단으로 정렬**되어 남는다.
- **이월(carry-over)**: 어제 미완료한 할 일은 자동으로 넘어오지 않는다. 앱을 열 때 **"어제 미완료 N개, 오늘로 가져올까?"**를 물어보고 사용자가 확인하면 오늘로 이월한다.

### 5-3. 일정 (Schedule) — v2

- 시작·종료 시각이 있는 이벤트(예: 11:00~11:30 회의).
- v1에는 없다. **Google Calendar 연동(v2)** 시 그날 등록된 일정을 **읽어와 ③에 표시만** 한다(앱 내 일정 편집은 범위 밖).

### 5-4. 포모도로 세션 + 소프트 프릭션 관문

```
[대기] 아무것도 차단 안 됨
   │  ③의 청록색 ▷ 버튼 클릭 (현재 선택된 그룹 컨텍스트에서 시작)
   ▼
[포모도로 세션 진행 중]
   유효 차단 목록 = 공통 제한 앱 ∪ (선택 그룹의 제한 앱)
   │  세션 중 차단 대상 앱을 포그라운드로 전환하면
   ▼
[전체화면 관문 오버레이] "지금 집중 세션 중입니다"
   ├─ [집중으로 돌아가기] → 세션 계속, 흐트러짐 기록 안 남음
   └─ [계속 쓸게]        → 세션 계속, '흐트러짐' 1회 기록
```

- **어떤 선택을 해도 세션은 끊기지 않는다.** 유일한 결과는 "기록에 남는다"는 것.
- 그룹을 선택하지 않은 전체 보기 상태에서 세션을 시작하면 유효 차단 목록 = **공통 제한 앱만**.

## 6. 차단 구조 (2-레이어)

| 레이어             | 켜지는 시점                     | 내용                                             |
| ------------------ | ------------------------------- | ------------------------------------------------ |
| 공통 제한 앱       | 어떤 포모도로 세션이든 항상     | 평소에 안 쓰고 싶은 앱 (예: 인스타그램, 유튜브)  |
| 그룹 제한 앱       | 그 그룹으로 세션을 돌리는 동안  | 그 맥락에 방해되는 앱 (예: '현대' → 디스코드)    |

- 세션 하나의 유효 차단 목록 = 공통 세트 ∪ 선택 그룹의 세트.
- 대기 상태(세션 없음)에서는 아무것도 차단되지 않는다 — 포모도로 세션이 차단의 전제조건.
- **v1은 앱(bundleId) 차단만.** "앱/사이트 추가" UI에 사이트 자리는 두되, **사이트 차단은 v2**(macOS에서 사이트 차단은 브라우저 확장/프록시/hosts 등 별도 방식 필요).

## 7. 기술 방향

- **플랫폼**: macOS 우선 (Windows는 추후 별도 엔진으로 확장 가능성 열어둠)
- **데스크탑 셸**: Electron + React + TypeScript (`electron-vite`)
  - 관문 오버레이는 `BrowserWindow`의 1st-party 옵션(`focusable: false`, 최상단 레벨)으로 포커스를 뺏지 않게 구현.
  - `electron-updater` 기반 자동 업데이트.
- **앱 감지 (네이티브 헬퍼)**: 별도의 작은 **Swift CLI 헬퍼 바이너리**
  - `NSWorkspace`의 앱 활성화 알림을 구독해 이벤트 발생 시 stdout으로 JSON 라인 emit.
  - Electron 메인 프로세스가 자식 프로세스로 스폰해 stdout을 스트림으로 읽음(폴링 아닌 이벤트 기반).
  - 앱은 `bundleId`로 매칭. 특수 권한(Family Controls 등) 불필요.
- **프론트엔드 데이터 레이어**: TanStack Query + axios — Kotlin Spring Boot REST API 호출, 캐싱·리페치·낙관적 업데이트("계속 쓸게" 직후 통계 즉시 반영).
- **스타일링**: Tailwind CSS + shadcn/ui (Radix 프리미티브 기반, 관문 같은 모달성 UI에 유리) + `next-themes` 다크모드.
- **백엔드 서버**: Kotlin + Spring Boot
  - **v1부터** 계정/로그인 + 데이터 저장(할 일·그룹·제한앱·세션·기록)을 담당하는 REST API 서버.
  - 데스크탑 앱과는 순수 HTTP 통신.
- **배포**: App Store 밖 배포 — Developer ID 서명 + 노터라이즈 (Cold Turkey, Freedom과 동일).

## 8. 데이터 모델 (요약)

핵심 엔티티:

- **USER** — 계정. 로그인/인증. (v1부터)
- **GROUP** — 할 일을 묶는 단위이자 제한 앱 스코프. USER에 속함.
- **TODO** — 할 일. GROUP·날짜에 귀속. 상태(미완료/완료), 서브태스크(자기참조 트리, v1 최대 3단계).
- **BLOCKED_APP** — 차단 대상 앱. `bundleId`로 저장. 스코프 = `COMMON`(공통) 또는 특정 `GROUP`.
- **FOCUS_SESSION** — 포모도로 세션 기록. 시작/종료 시각, 연결된 GROUP(및 선택적으로 TODO), 세션 시작 시점의 유효 차단 목록 스냅샷(`blocklistSnapshot`).
- **DISTRACTION_EVENT** — 세션 중 차단 앱을 열려 한 사건. `outcome`이 `returned`(저항 성공) 또는 `proceeded`(흐트러짐).

관계 요약:

- USER → GROUP → TODO: 1대다 계층.
- TODO → TODO(서브태스크): 자기참조 1대다 (v1 최대 3단계).
- BLOCKED_APP: 스코프가 `COMMON`이거나 특정 GROUP에 귀속.
- FOCUS_SESSION → GROUP: 필수(전체 보기 세션이면 공통만), → TODO: 선택.
- FOCUS_SESSION → DISTRACTION_EVENT: 1대다.
- 상세 스키마는 별도 문서(`01. data-model.md`, 추후 작성) 참고.

## 9. 통계 / 게임화

"계속 쓸게"의 유일한 대가가 기록이기 때문에, 그 기록이 사용자에게 실제로 와닿아야 관문이 의미를 가진다.

- **v1(최소)**: 연속 집중 **스트릭** + **흐트러짐 카운트**.
- **이후**: 집중도 점수(세션당 흐트러짐 기반), 세션별 저항 성공/흐트러짐 비율, 앱별 유혹 랭킹.
- 세부 산식과 UI는 별도 문서(`02. stats-gamification.md`, 추후)에서 다룬다.

## 10. 버전 로드맵

**v1 (MVP) — Calendar 탭**

- 그룹 CRUD
- 할 일 CRUD (그룹·날짜 귀속, 서브태스크 최대 3단계, 완료 시 하단 정렬 유지)
- 주간 뷰 + 날짜 이동 + 미완료 수동 이월 확인
- 제한 앱 등록 (공통 세트 + 그룹별 세트, bundleId)
- 포모도로 세션 (③의 ▷ 버튼) + NSWorkspace 앱 감지 + 전체화면 소프트 프릭션 관문
- 세션/흐트러짐 기록 저장
- 최소 통계 (스트릭, 흐트러짐 카운트)
- **계정 생성/로그인 + 백엔드 DB 저장** (v1부터)

**v2**

- Google Calendar 연동 (그날 일정 읽어와 표시)
- 사이트 차단
- (필요 시) 결제/구독 연동

**v3**

- Friends 탭 — 친구들이 어떤 TODO를 하고 있는지 탐색
